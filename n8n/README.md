# أتمتة نظام المدرسة عبر n8n

هذا المجلد يحتوي على ورش عمل (workflows) جاهزة للاستيراد في [n8n](https://n8n.io) لأتمتة أربع خدمات فوق نظام `tasks-app` الحالي، دون أي تعديل على كود التطبيق:

| # | الملف | الوظيفة | الجدولة الافتراضية |
|---|------|---------|---------------------|
| 1 | `1-absence-late-notifications.json` | إشعار واتساب لولي الأمر عند تسجيل غياب/تأخر الطالب | يومياً 11:00 |
| 2 | `2-daily-admin-report.json` | تقرير يومي بالبريد لمدير المدرسة (غياب، زوار، حالات، مهام، فاقد تعليمي) | يومياً 13:30 |
| 3 | `3-weekly-reports.json` | تقرير أسبوعي بالبريد للوكلاء الثلاثة (معدل الحضور + الفاقد التعليمي) | كل خميس 14:00 |
| 4 | `4-nightly-backup.json` | نسخة احتياطية كاملة من بيانات النظام إلى جدول Supabase منفصل | يومياً 02:00 |
| 5 | `5-staff-reminders.json` | تذكيرات داخلية بالمهام المستحقة/المتأخرة، متابعات المرشد، والحصص الشاغرة | يومياً 07:30 |

## كيف تتصل ورش العمل بالنظام؟

النظام لا يخزّن بيانات في جداول منفصلة، بل يحفظ كل الحالة (الطلاب، الحضور، الموظفون، المهام...) كسجل JSON واحد في جدول `app_data` بـ Supabase (نفس آلية المزامنة السحابية المستخدمة في `app.js`). لذلك كل ورش العمل تعمل بنفس النمط:

1. **Schedule Trigger** يشغّل الورشة في وقت محدد.
2. **HTTP Request** يجلب السجل عبر Supabase REST API باستخدام نفس مفتاح `anon` الموجود أصلاً في `app.js` (مفتاح عام محمي بسياسات RLS، وليس سرّاً — نفس المفتاح المرسَل من متصفح أي مستخدم للنظام).
3. **Code** (JavaScript) يستخرج من الـ JSON البيانات المطلوبة لكل خدمة (غياب اليوم، مهام مستحقة، إلخ).
4. عقدة إرسال (بريد / واتساب عبر Twilio / حفظ نسخة احتياطية) تنفّذ الإجراء النهائي.

لا حاجة لإضافة أي Webhook داخل `app.js` — كل الاستيراد للبيانات يتم بجلب دوري (polling) من Supabase مباشرة.

## خطوات التركيب

1. **استيراد الورش**: في n8n، من قائمة Workflows اختر *Import from File* وحمّل كل ملف من `workflows/` على حدة.
2. **إشعارات واتساب (ورشة 1)**: أنشئ اعتماد (Credential) من نوع Twilio في n8n وحدد رقم واتساب معتمد (أو رقم Twilio Sandbox للتجربة)، ثم اربطه بعقدة "إرسال واتساب لولي الأمر". أرقام أولياء الأمور تُقرأ تلقائياً من حقل `جوال ولي الأمر` في بيانات كل طالب — تأكد أن الأرقام مسجَّلة بصيغة سعودية محلية (05xxxxxxxx).
3. **البريد (ورش 2، 3، 5)**: أنشئ اعتماد SMTP في n8n واربطه بعقدة "إرسال ... بالبريد" في كل ورشة. عدّل عقدة **"إعدادات المستلمين (عدّل هنا)"** في بداية كل ورشة وضع البريد الفعلي لمدير المدرسة/الوكلاء بدل القيم التجريبية `@example.com`.
4. **النسخ الاحتياطي (ورشة 4)**: أنشئ في Supabase جدولاً جديداً باسم `app_data_backups` بالأعمدة:
   ```sql
   create table app_data_backups (
     id uuid primary key default gen_random_uuid(),
     data jsonb not null,
     created_at timestamptz not null default now()
   );
   alter table app_data_backups enable row level security;
   create policy "allow anon insert" on app_data_backups
     for insert to anon with check (true);
   ```
   هذا يسمح فقط بالإدراج (لا قراءة ولا تعديل) بنفس مفتاح `anon` العام. إن رغبت بحماية أعلى استبدل الهيدرين `apikey`/`Authorization` في عقدة الحفظ بمفتاح Service Role (يُحفظ حصراً داخل n8n ولا يُشارك).
5. **المنطقة الزمنية**: كل الورش مضبوطة على `Asia/Riyadh`. تأكد أن إعداد Timezone في n8n نفسه مطابق، أو عدّل حقل `settings.timezone` وساعات التشغيل داخل كل ملف حسب الحاجة.
6. فعّل (Activate) كل ورشة بعد التأكد من الإعدادات.

## ملاحظات أمنية

- بيانات الطلاب (الاسم، جوال ولي الأمر) حساسة — تأكد من تأمين الوصول لواجهة n8n بمصادقة قوية (2FA) وقصر الصلاحيات على من يحتاجها فعلاً.
- مفتاح `anon` المستخدم للقراءة هو نفسه المستخدم في تطبيق الويب أصلاً (عام بتصميم Supabase، وأمانه معتمد على سياسات RLS في قاعدة البيانات وليس سرّية المفتاح)، لذلك تضمينه هنا لا يضيف مخاطرة إضافية عن الوضع الحالي.
- عند تفعيل ورشة النسخ الاحتياطي، راقب حجم جدول `app_data_backups` بمرور الوقت وأضف مهمة دورية لحذف النسخ الأقدم من مدة معينة إن رغبت.
